# Shared Project Folder Feature

## Overview
When a new project is created in the system, a **Shared Project Folder** is automatically generated. This folder serves as a centralized hub for all project-related inputs, documents, and resources that team members need to access and manage throughout the project lifecycle.

## What is the Shared Project Folder?

The shared project folder is automatically created with the naming convention:
```
Shared - [Project Name]
```

**Example:** If you create a project named "E-Commerce Platform", a folder named "Shared - E-Commerce Platform" is automatically created.

## Folder Structure

```
Client Root
└── Shared - [Project Name]     ← Auto-created shared project folder
    ├── Architecture Documents
    ├── Requirements & Specifications
    ├── Meeting Notes
    ├── Design Mockups
    ├── API Documentation
    ├── Database Schemas
    └── Other Project Resources
```

## Access & Permissions

- **Who can access:** All team members assigned to the project (regardless of role)
- **Accessibility:** Role-neutral - Architects, Developers, Experts, SUL, and Sales personnel can all access and contribute
- **Upload permissions:** All authenticated project team members
- **File types:** Documents, PDFs, images, spreadsheets, code files, design files, etc.

## What to Store in the Shared Folder

All project-related inputs and information should be stored here:

### Documentation & Requirements
- Meeting notes and MOM (Minutes of Meeting)
- Project requirements documents
- Feature specifications
- User stories and acceptance criteria
- Client feedback and change requests

### Technical Resources
- Architecture diagrams and documentation
- Technology recommendations
- Database schemas and designs
- API documentation
- Infrastructure specifications
- Deployment guides

### Design & Specifications
- UI/UX mockups and wireframes
- Design system documentation
- Component specifications
- Branding guidelines

### Project Management
- Project timeline and milestones
- Resource allocation documents
- Cost estimations and budgets
- Risk assessments
- Project status reports

### Code & Configuration
- Source code references
- Configuration files
- Build scripts
- Deployment scripts
- Environment setup guides

## How to Use

### 1. **Uploading Files**
- Navigate to the project's client folder in the Documents section
- Locate the "Shared - [Project Name]" folder
- Click "Upload File" to add documents, resources, or any project-related files

### 2. **Organizing Files**
- Create subfolders within the shared project folder for better organization
- Use clear naming conventions for documents
- Organize by document type or project phase (e.g., Requirements, Design, Development)

### 3. **Accessing Files**
- All project team members can browse and download files from the shared folder
- Files are available in the folder structure view
- Version history is maintained for tracking changes

### 4. **Collaborative Access**
- Team members can contribute and upload files to the shared folder
- All team members see the latest versions
- Changes are logged in the audit trail

## Benefits

✅ **Centralized Information** - All project inputs in one place
✅ **Team Collaboration** - Easy sharing between architects, developers, and other roles
✅ **Reduced Clutter** - No scattered project files across multiple personal folders
✅ **Accessibility** - All team members have equal access to project resources
✅ **Audit Trail** - Track who uploaded/modified files and when
✅ **Version History** - Maintain history of project documents
✅ **Easy Onboarding** - New team members can quickly find all project information

## Best Practices

1. **Use Consistent Naming** - Use clear, descriptive file names
2. **Organize Regularly** - Create subfolders for different document types
3. **Update Documentation** - Keep project documents current
4. **Remove Outdated Files** - Archive or delete old versions
5. **Add Descriptions** - Use folder descriptions to explain contents
6. **Archive Completed Phases** - Move completed phase documents to subfolders

## Automatic Creation

- Shared project folders are **automatically created** when a project is first registered
- No manual setup required
- The folder is immediately accessible to all project team members

## Integration with Chat Groups

- Project team members can reference shared folder documents in project chat groups
- File links from the shared folder can be shared in chat messages
- Facilitates collaborative discussions around project resources
